# 安全审计 (security-audit)

对目标代码库执行自动化 + 人工复核相结合的安全审计, 覆盖以下核心诉求:

1. **敏感信息泄露** —— 代码中硬编码的密码、密钥、令牌、连接串等
2. **SQL 注入等漏洞风险** —— 字符串拼接 SQL、未参数化查询等
3. **配置文件明文敏感信息** —— `*.properties/.yml/.env/.conf` 中的明文凭证
4. **其他安全隐患** —— 命令注入、不安全反序列化、弱密码学、路径遍历、XSS、认证授权缺陷、依赖漏洞等

## 何时使用

- 用户明确要求"安全审计 / 安全检查 / 找漏洞 / 排查敏感信息泄露"
- 用户提交代码前/后希望做安全审查
- 修复安全缺陷后做回归验证

## 工作流程

### 第 1 步: 运行自动化扫描器

优先使用随技能提供的扫描脚本获取确定性线索(避免人工逐文件遗漏):

```bash
python <skill_dir>/scripts/security_audit.py <目标路径> --format markdown --output <报告路径>.md
```

常用参数:
- `<目标路径>`: 目录(默认递归)或单个文件
- `--format {text,json,markdown}`: 输出格式(默认 text)
- `--strict`: 存在 HIGH 级问题时以非零状态码退出(适合 CI)
- `--max-size BYTES`: 单文件大小上限, 默认 1MB
- `--no-skip-vcs`: 默认会跳过 `.git`、`node_modules`、`target`、`.codebuddy` 等目录

> 扫描器为**启发式正则扫描**, 结果仅为"可疑线索", 必须人工复核确认(存在误报/漏报)。
> 建议对扫描命中的每一条, 打开对应文件核实真实上下文。

### 第 2 步: 参照检查清单做人工复核

加载 `references/audit_checklist.md`, 对照其中 10 大类逐项检查, 重点补齐脚本**无法覆盖**的部分:
- 业务逻辑漏洞: IDOR(越权访问他人资源)、缺失后端鉴权、权限仅前端校验
- 路径遍历、XSS、依赖供应链漏洞(`npm audit` / `mvn dependency-check` / `pip-audit` 等)
- 已提交到 git 历史中的敏感信息(脚本不扫历史, 可用 `git log -p` 或 gitleaks 补充)

### 第 3 步: 汇总并输出报告

向用户输出结构化报告, 至少包含:
- **概览**: 命中总数、各严重级别数量(HIGH/MEDIUM/LOW)
- **明细**: `文件:行号`、类别、严重级别、描述、命中片段、修复建议
- **优先级**: 先修 HIGH(凭证泄露、注入、RCE 类)
- **误报标注**: 明确哪些需用户确认
- **修复指引**: 对每条给出可操作建议(参考 checklist 的修复项)

## 报告格式示例

```markdown
## 安全审计概览
- 总计: 12  高危: 3  中危: 5  低危: 4

### 1. [HIGH] 硬编码凭证
- 文件: backend/src/main/resources/application.yml:15
- 规则: CONFIG_PLAINTEXT_SECRET
- 描述: 配置文件中存在明文数据库密码
- 修复建议: 改为 ${DB_PASSWORD} 占位符, 通过环境变量注入, 并轮换密码
```

## 关键约定

- 发现**已泄露的密钥/密码**: 提示用户"立即轮换", 而不仅仅是删除——已提交的内容可能已被复制。
- 不主动修改用户代码来"修复"安全问题, 除非用户明确要求; 默认只**诊断并给出建议**。
- 若用户希望自动修复, 在得到确认后再对指定文件做最小化、可逆的修改。
